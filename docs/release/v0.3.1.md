# h2-net v0.3.1 - Client

**Both sides of an HTTP/2 connection, without I/O, and the first release on crates.io.** v0.3.1 adds the client side to v0.3.0's codec and server connection.

## What is h2-net?

<strong>h2-net</strong> is HTTP/2 the way http-net is HTTP/1.1: a sans-IO engine that refuses what it cannot frame unambiguously and bounds every buffer. The caller owns sockets, threads, and timers. It is `no_std` with `alloc`, `#![forbid(unsafe_code)]`, and its one dependency is http-net.

## What's new in 0.3.1

### The client connection (`h2_net::conn::ClientConn`)

- The same connection as the server side, from the other end, for outbound HTTP/2: the protocol, flow control, and every budget are shared, so a fix on one side is on both.
- Requests go out with `send_request` from `RequestParts`; at the server's stream limit it waits with `SendError::Busy`.
- Responses are checked by RFC 9113 section 8.3 and reported as `Event::Response`, with informational heads as `Event::Informational`. A malformed response resets its stream.
- Server push is refused.
- The streams a `GOAWAY` left unprocessed are reported as reset with `REFUSED_STREAM`, so they can be retried.

### Changed

- `ServerConn` is now `Connection<Server>`, an alias; nothing a server's code calls changed.

## Checks

- Seven fuzz targets, a client facing a hostile server among them. CI runs each for 60 s; a 20-minute run of each found nothing.

## Upgrading

v0.3.0 was released on GitHub only, so 0.3.1 is the first version on crates.io:

```toml
[dependencies]
h2-net = "0.3"
```

## What's next

serve-net's HTTP/2 support, built on this release: ALPN `h2` selects h2-net, and cleartext HTTP/2 is served behind a trusted proxy.
