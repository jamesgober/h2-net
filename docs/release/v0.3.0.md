# h2-net v0.3.0 - Engine

**HTTP/2 for a server, without I/O.** v0.3.0 is the first functional release: the frame layer, HPACK, and the server side of a connection, with a budget against every known HTTP/2 attack. It takes the place of the planned 0.2.0 (the codec alone), which was not released on its own.

## What is h2-net?

<strong>h2-net</strong> is HTTP/2 the way http-net is HTTP/1.1: a sans-IO engine that refuses what it cannot frame unambiguously and bounds every buffer. The caller owns sockets, threads, and timers. It is `no_std` with `alloc`, `#![forbid(unsafe_code)]`, and its one dependency is http-net.

## What's in 0.3.0

### Frames (`h2_net::frame`)

- Every frame type of RFC 9113, and `PRIORITY_UPDATE` from RFC 9218, read as borrowed views and written back.
- Every check RFC 9113 puts on a frame by itself.
- A frame longer than `SETTINGS_MAX_FRAME_SIZE` is refused from its 9-byte header, before its payload is buffered.
- The encoder refuses whatever the decoder would refuse, so a decoded frame always encodes back to itself.

### HPACK (`h2_net::hpack`)

- A decoder and encoder with bounded dynamic tables and Huffman coding.
- A field block decodes into a `HeaderList` whose budget is checked before each field is copied. A one-byte index naming a 4 KB entry, repeated a thousand times, stops at the budget.
- A block over the budget still keeps the dynamic table in step, so the request can be refused without closing the connection.
- The encoder never indexes credentials.
- The static table and Huffman code are generated from RFC 7541's text. Every Appendix C example decodes byte for byte.

### The server connection (`h2_net::conn`)

- `ServerConn`: feed it bytes, poll for events, write out what it produces.
- It answers `SETTINGS` and `PING`, runs flow control in both directions, and shuts down gracefully in RFC 9113's two steps.
- Request bodies are not buffered: the application releases bytes as it deals with them, which is what holds back a peer that sends faster than the application reads.
- Requests arrive as http-net's `OwnedRequestHead`. Each request is checked by RFC 9113 section 8, then written out as the HTTP/1.1 head a translating proxy would send and parsed by http-net. HTTP/2 and HTTP/1.1 requests get the same type and the same strictness.
- Responses go in as a status and fields; HTTP/1.1's connection fields are dropped, so an HTTP/1.1 response maps across unchanged.
- RFC 9218 priorities are read from the `priority` field and `PRIORITY_UPDATE` frames and reported with each request. Ordering responses is the driver's job.

### Budgets

Each budget weighs what the peer costs against the work it asked for, so none needs a clock. Each ends the connection with `ENHANCE_YOUR_CALM` and sets `ConnError::is_abuse()`, which a connection gate can count against the address.

| Attack | Budget |
|---|---|
| Rapid reset (CVE-2023-44487), and resets the peer provokes with bad frames | resets over a floor of 200 and over 4 times the responses completed |
| `CONTINUATION` floods | 64 KiB and 32 frames per field block, empty frames included |
| `SETTINGS`, `PING`, priority, empty `DATA`, and unknown-frame floods | over a floor of 1000 and over 10 times the work received |
| A peer that sends but never reads | at most 1000 unread answers, and a bounded output |
| Stream exhaustion | 100 concurrent streams; the rest are refused |
| HPACK bombs | the request is answered `431` and the connection goes on |

Every budget has an attack test that it stops, and the same test shows the attack getting through with that budget turned off.

## Checks

- Six fuzz targets: the frame decoder, the HPACK decoder, the HPACK round trip, the Huffman code, the priority field, and the server connection. CI runs each for 60 s.
- Benchmarks on one development machine:
  - 2.9 ns to decode a frame.
  - 436 ns to decode a 17-field browser request with a warm table.
  - 2.4 µs for a whole request and its response on one connection.

## What's next

serve-net's side: an engine slot for several streams per connection, with ALPN `h2` selecting h2-net. After that, the client side.
